# novel2drama 需求与架构（精简搬运）

> 权威全文见 `/root/vault/40-项目/AI漫剧-小说转单集工作流架构-20260822.md` 与 API 设计档。此处仅保留本项目实现所需要点。

## 流程
小说原文 → 人机协同分镜编辑 → 分镜确认 → 角色/场景资产确认 → Z-Image 段首关键帧 → 人工复核 → H3 15s 段 → 人工复核 → 多段拼接 → 单集导出。

## 关键概念
- **分镜**：不是逐镜头生成视频，而是规划 15s 段内部镜头节奏（1-3s 一个节拍），汇总成连续时序 prompt（H3 用）。
- **Z-Image**：角色/场景资产图 + 15s 段首关键帧。
- **H3**：段首图 + 15s 连续 prompt → 一段 15s 视频。
- **单集 = 多个 15s 段顺序拼接**（2min≈8段，3min≈12段）。

## 页面
项目列表 / 小说编辑 / 分镜协同（左原文 中段列表 右段详情+节拍）/ 资产复核 / 段首图复核 / 15s 段复核 / 成片导出。

## 职责分工
- Web+后端：项目管理/小说/分镜协同/人工复核/任务调度/版本追踪/拼接导出。
- ComfyUI：Z-Image / H3 生成。
- LLM：分镜生成/镜头补全/剧情压缩/H3 prompt 汇总（走 smmmc，不占本地显存）。
- ffmpeg：多段拼接。

## 15s 段 / 节拍字段
- Segment：segment_id/段编号/剧情摘要/段首衔接/段尾衔接/角色资产引用/场景资产引用/段首图/H3 prompt/生成状态。
- ShotBeat：beat_id/起止时间/时长/景别/运镜/角色动作/场景变化/光线/构图/风格/情绪/衔接方式。

## 技术
- 后端 FastAPI；前端 Jinja2 + 原生 JS（app.js，非 HTMX）；SQLite；本地 data 存储；GPU 单 worker 串行队列；部署 GPU systemd + nginx basic auth。

## 资产一致性（双级确认）
资产 prompt → Z-Image 抽卡 → 人工选定 → image2 高质量预览 → 人工确认 → 资产入库。
