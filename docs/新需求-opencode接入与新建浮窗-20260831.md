## 需求 A：opencode(ACP) agent 接入 + n2d CLI 工具

**目标**：小说工作台页面上可直接指示一个 AI 编码 agent 修改剧情等，agent 通过 n2d CLI 操作 novel2drama 后端数据。

**现状（已诊断确认）**：
- GPU 服务器 36.138.26.41：opencode 1.18.18 已装（`/usr/local/bin/opencode`），支持 `opencode acp`（Agent Client Protocol，stdio 上换行分隔 JSON-RPC）。
- n2d CLI 已装 `/usr/local/bin/n2d`，直连 workbench 后端 `127.0.0.1:8010`。
- workbench = FastAPI（GPU `127.0.0.1:8010`），systemd `novel2drama.service`，`/usr/bin/python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8010`，EnvironmentFile `/etc/novel2drama.env`（LLM_BASE_URL=https://api.smmmc.cn/v1, LLM_MODEL=deepseek-v4-pro, 有 LLM_API_KEY）。
- opencode 至今无模型凭据（`opencode auth list` = 0）。
- opencode 配置目录 `/root/.config/opencode/`（空）。

**已拍板决策**：
1. **模型供应商**：smmmc（https://api.smmmc.cn/v1），模型 = `deepseek-v4-flash-vision-exp`，复用 `/etc/novel2drama.env` 的 LLM_API_KEY。
2. **n2d 工具化**：不包 MCP；让 opencode 用自带 bash 工具直接跑 `n2d ...`，通过 AGENTS.md 引导用法。
3. **审批**：n2d 写操作 → 前端弹窗确认（**不展示原始命令**，整理成高可读的**行为卡片**）；读操作 → 自动放行。其余工具操作同理（写/改 → 卡片确认）。
4. 前端对话窗浮窗与需求 B 的弹窗/浮窗风格统一。

**ACP 协议要点（落地依据）**：
- 传输：stdio 子进程；JSON-RPC 2.0，消息**换行分隔**，不许内嵌换行；stderr 可收藏日志，stdout 只许 ACP 消息。
- 流程：`initialize` → `session/new`(带 cwd / tools) → `session/prompt` → agent 以 `session/update` 通知回传 plan / `agent_message_chunk` / `tool_call` / `tool_call_update` / `usage_update`；`session/request_permission`(请求带 id)待客户端 approve/deny；`session/prompt` 响应 `stopReason`(end_turn/cancelled/...)。
- 取消：`session/cancel` 通知。
- 官方 Python SDK：`pip install agent-client-protocol`（Pydantic 模型 + JSON-RPC plumbing，agent 与 client 两侧都有）。

**后端新增**（workbench，GPU）：
- `app/services/acp_client.py`：async 实现 ACP client —— spawn `opencode acp` 子进程，stdio JSON-RPC；按 sessionId 分发 `session/update` 到 per-session 队列；管理 prompt future / permission future；读操作自动 approve，写操作挂起等待前端决策并回写。
- `app/routers/agent.py`：API 路由
  - `POST /api/v1/agent/chat` → 建立/复用 session，发起 prompt，返回 `StreamingResponse(SSE)`，流式下发 update（文本 chunk、行为卡片、工具状态、完成）。
  - `POST /api/v1/agent/permission/{permission_id}` → 用户在前端对行为卡片 approve/deny，回写 ACP。
  - `POST /api/v1/agent/cancel` → `session/cancel`。
  - `GET /api/v1/agent/status` → 进程/会话健康。
- `AGENTS.md`（放 `/data/projects/novel2drama/`，opencode session cwd 指向此处）：说明项目结构 + n2d CLI 完整用法 + 修改剧情的工作约定。
- opencode 供应商配置：写 `/root/.config/opencode/opencode.json`（custom provider smmmc / deepseek-v4-flash-vision-exp / api key）。

**前端新增**：
- 全局「AI 助手」浮窗入口（右下角），打开聊天抽屉；用 EventSource(SSE) 收流式内容。
- 行为卡片渲染：opencode 请求写操作时，前端把带出参的 n2d/bash 意图解析为中文「行为卡片」（如“修改第3段剧情摘要 → …”），含 批准/拒绝 按钮 → POST permission 接口。**禁止直接显示原始命令字符串。**
- 展示 agent 思考流、工具调用状态（进行中/完成）、最终结果。

**交互约定（行为卡片解析）**：后端把 n2d 命令映射为中文描述。读命令自动放行；写命令（段/章/项目/资产/分集的新建、编辑、删除、确认、激活、parse、generate、select 等）转卡片确认。
- 写命令清单：`project new/rm`、`novel new/activate`、`chapter parse/edit/rm`、`seg new/edit/rm`、`beat new/edit/rm`、`asset new/confirm`、`keyframe generate/select`、`jobs`(gen) 等。
- 读命令清单：`projects/project detail`、`novels/novel detail`、`chapters/chapter`、`segments/seg/beats`、`assets/builds/kframe view/exports` 等。

### 已验证结论（实测 opencode 1.18.18 ACP）
- 传输：stdio 换行分隔 JSON-RPC。
- `initialize` → `session/new{cwd,mcpServers}`→返回 `sessionId`（字符串，勿用消息 id 当 sessionId）。
- `session/prompt{sessionId,prompt:[{type:text,text}]}` → 响应 `{stopReason,...}`。
- 流式通知：`agent_message_chunk` / `tool_call` / `tool_call_update` / `usage_update`。
- **权限请求**：`session/request_permission` params `{toolCall:{title,kind,rawInput:{command}}, options:[{optionId,kind,name}]}`。
- **批准响应（关键坑）**：`{"jsonrpc":"2.0","id":reqId,"result":{"outcome":{"outcome":"selected","optionId":"once|always|reject"}}}`。
  （错误写法 `result:{optionId:...}` 或 `result:{outcome:"approved"}` 均导致 agent 被拒/静默——已实测修正。）
- opencode 默认直接执行工具（不询问）；`"permission":{"bash":{"*":"ask"}}` 后才会发 `request_permission`。
